# Performance: measure it, then fix what the measurement names

Performance work in this app has been wrong by intuition more often than right. The rule: measure on the real thing, find the mechanism, fix that, measure again, and write the before/after in the commit. Say which build the numbers come from (a dev build's React is several times slower than production; a percentage from one is a direction, not a prediction). Animation and compositor cost has its own doc: [idle energy](idle-energy.md).

## How to measure (works on the dev app, no code changes)

Start it with `npx electron-vite dev --remoteDebuggingPort 9333` and drive it over CDP from a small Node script (`fetch('http://localhost:9333/json')`, then a WebSocket to the page):

- `Runtime.evaluate` for DOM facts. A module's live instance is reached with `import(<its URL from performance.getEntriesByType('resource')>)`: importing the bare path after an HMR update gives a second copy of the module and silently measures nothing.
- `Profiler.start/stop` for where main-thread time goes. Group samples by the outermost app frame, not by self time, which drowns in React internals.
- `document.getAnimations()` for what is keeping the compositor busy.
- Patch `ResizeObserver.prototype.observe` / `setTimeout` for a few seconds to count who calls them; `Input.dispatchMouseEvent` (`mouseWheel`, `modifiers: 2`) for zoom/pan gestures.
- Process CPU from `ps -o time` deltas of the renderer and GPU processes (not `%cpu`, which is a lifetime average). Tile/raster trouble shows as `tile memory limits exceeded` in the dev log.
- For SSH: the host's `journalctl -u ssh | grep -c 'Accepted publickey'` over the test window says whether multiplexing held (healthy is about 0 to 1 per connect).

## Rules this produced

- **One running animation keeps the whole window at display rate.** Status animations are bounded (they settle lit), never infinite, except needs-you. Measured on a 46-node canvas: idle renderer+GPU about 120 % to about 25 % (#1050). Details in [idle energy](idle-energy.md). An infinite CSS animation must carry `animation-play-state: var(--nt-anim-state);`, and a dependency's stylesheet counts too.
- **Never promote the React Flow viewport** (`will-change: transform`). It is a canvas-sized layer; on a real canvas it overran the tile budget (flicker) with no CPU gain (#1047).
- **A `backdrop-filter` is re-run every time its surface is drawn, and nothing caches it**, neither for the surface's own content changes nor when moved to a sibling layer under the content (both measured). Glass on anything that updates often (a terminal) costs a full blur per update, and pixel-moving filters spread the damage to neighbouring glass. A plain `filter` on content that does not change is reused. Liquid Glass terminals therefore frost a static wallpaper copy (`.term-node__frost`, `lib/glassFrost.ts`): six streaming terminals went 92 % to 42 % GPU. An SVG `feImage` in a filter chain marks its whole surface damaged, so keep reference filters off surfaces that redraw. The refraction filter (`url(#nt-refract)`) runs only left of the Readable tick for the same reason. See [appearance](appearance.md).
- **An all-filtered node-change batch must not reach `onNodesChange`** (`handleNodesChange` returns early). `applyNodeChanges([])` returns a new array; a new `nodes` rebuilds the ephemeral subagent/loop cards without `measured`, React Flow re-observes them and its ResizeObserver (`force: true`) emits another change, so the whole Canvas re-rendered every frame while idle with one subagent card on screen (about 111 % to about 55 % idle, #1047; `canvas-empty-changes.test.ts`).
- **Per-terminal work on a project switch must be coalesced and ordered.** A switch mounts every node in one tick. Join an in-flight read instead of issuing one per node (the SSH project's settings.json read, `overridesInFlight` in pty-manager), and let on-screen nodes go first (`PtyCreateOptions.onScreen` to `pty-spawn-gate.ts`). On a 41-terminal SSH project the visible ones went from painting last (1.5 to 2.1 s) to first (0.55 to 1.1 s), with 0 extra logins (#1057).
- **A hint must fail toward the old behavior.** `onScreen` absent or unknown means on screen, the old FIFO. A coalesced read is never a cache (a spawn after it settles reads again).
- **Search a large in-memory text set with one case-insensitive RegExp per query, never by lower-casing each entry.** The transcript index (`core/transcript-index-core.ts`, `queryRegExp`) lowered every entry per keystroke: 20 to 52 ms and 7 to 15 MB garbage per search on a 16 MB index, vs 2 to 13 ms and 0 MB as one `RegExp(escaped, 'iu')`. A stored lowered copy would retain +32 MB. Use `iu`, not `i`: `i` loses hits `toLowerCase` found (Kelvin K, Å, ẞ). Escape only SyntaxCharacters and `/` (`\-` is a SyntaxError in `u` mode). Even `iu` loses Turkish İ (it lowers to `i` + U+0307, so `türki` matched `TÜRKİYE`), so each i/I of the escaped query is widened to `[iİ]`. The snippet uses the same matcher. The index file persists through `writeFileAtomic` (0600), only when a `dirty` flag says the file is behind.
- **macOS memory pressure comes from the kernel's level** (`onKernelPressure` in `core/memory-pressure.ts`), fired on escalations only, and at the same severity at most once per `KERNEL_LEVER_GAP_MS` (a level flapping normal/warn re-arms it on every fall). Never re-fire it on a held level, and never route it through `hostMemReader`/`MemInfo`: the session reaper shares that reader.
- **A terminal under the kanban board must not draw.** CSS can't stop xterm; its render pause is `terminal/board-render-pause.ts`. Every "is the board up" check includes the Omni board (`isGlobalKanbanOpen()`), and the board never feeds the visibility verdict that drives hibernation and the WebGL budget. See [idle energy](idle-energy.md).
- **Dispose every Monaco model your node creates when it unmounts.** The TS/JS worker (a whole compiler isolate) is only stopped once no TS/JS model is left (`renderer/editor/tsWorkerReaper.ts`).

## Lazy imports on the main process

`ssh2` and `electron-updater` load on first use, never at main's module scope, which runs before Chromium's `ready` (together about 50 to 70 ms warm on every launch). Use `import type` for their types; values come from `ssh2()` in `native-mux.ts` and `initUpdater`'s `loadUpdater`. `src/main/lazy-deps.source.test.ts` goes red on a value import. A `require()` is not reached by `vi.mock`, so a test injects its double (see the updater tests). Details for ssh2 are in [native SSH on Windows](native-ssh-windows.md).
